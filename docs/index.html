项目解决什么问题

产品团队不缺评论，缺的是能追溯依据的分诊结果。

应用商店、社区和客服里的反馈常常混在一起：有人在抱怨模型不准，有人在说页面卡住，也有人提出企业知识库这种新需求。这个项目把评论整理为结构化表格、问题卡片、QA 报告和人工复核队列，方便产品面试官和技术读者检查每一步判断。

真实样例数据来自 AI 应用评论

v0.9.1 展示页对应的是可由 `data/ai_app_reviews.csv` 重新生成到 `data/output_ask` 的本地输出快照。样本覆盖豆包、DeepSeek、Kimi，来源包括 App Store、应用宝和小米应用商店，也可以通过线上 Vercel Demo 或本地 Web App 体验同一套流程。

输入只要求五列 CSV

当前 Agent 的标准输入字段是 `id`、`source`、`app_name`、`review_text`、`rating`。旧项目数据先通过准备脚本转换为这个格式，再进入同一套 Agent runner。

idsourceapp_namereview_textrating idsourceapp_namereview_textrating

输出不是一句总结

它会生成问题卡片、QA 报告、run log、结构化结果、产品周报摘要、人工复核队列、`review_decisions.csv` 和静态 HTML 报告；人工决策可继续生成 reviewed 结果。

LLM 是可选初稿

LLM 默认关闭；明确启用但没有 `DEEPSEEK_API_KEY` 时自动 fallback 到 `rules.py`。优先级和复核队列仍由本地规则处理。

人工复核不是装饰

P0、低置信度、多问题命中、文本过短等样本不会被自动闭环，会进入复核列表。

Agent 做了什么

固定七步，不靠临场发挥。

主流程保持稳定：读取输入、校验字段、分诊分类、识别 badcase、生成问题卡片、QA 检查、导出报告。自然语言 `ask` 命令只是入口，内部仍调用同一个 runner。

运行计划

1load_feedback
读取 CSV，记录行数和字段。
2validate_schema
检查必填字段和空值。
3classify_feedback
可选 DeepSeek 初稿，失败或无 key 时使用规则。
4detect_badcases
识别 P0、低置信度、多问题命中等复核原因。
5generate_issue_cards
为每条反馈生成可读问题卡。
6qa_check
汇总分布、fallback、复核队列。
7export_report
导出问题卡片、QA 报告、run log、结构化 CSV 和产品周报。

为什么还需要人工复核

Agent 可以排序和标记风险，但不能替产品负责人签字。

反馈里经常有多重问题、强烈情绪、隐私风险或上下文缺口。这个项目的边界是“先分诊，再交给人复核”，而不是自动决定产品动作。

P0 或投诉风险必须复核

例如隐私泄露、扣费、数据丢失、投诉、卸载等关键词。它们会影响信任和业务风险，不能只看规则结论。

低置信度分类补上下文

当评论过短或没有命中明确关键词时，Agent 会把它放入复核队列，避免把含糊反馈包装成确定结论。

同时命中多个问题拆分处理

同一条评论可能同时包含模型质量、页面卡顿、复制交互。它需要人工拆成多个可跟进问题，而不是合并成一个泛泛建议。

本次样例报告的复核压力

在 `data/output_ask` 中，30 条样本里有 21 条进入人工复核。这个比例高，不是系统失败，而是说明样例数据里有大量低置信度、多问题或高风险评论。

最后输出了什么

面试官可以看页面，技术读者可以追文件。

展示页面面向不会跑 CLI 的读者；样例报告展示真实导出结果；原始 markdown、CSV 和 HTML 仍保留，便于检查 run log、QA 报告、人工复核队列和每条问题卡片。

issue_cards.md

每条反馈一张问题卡，包含代表样本 ID、摘要、问题类型、优先级、用户需求、产品建议和复核原因。

qa_report.md

记录总览、LLM 是否使用、fallback 原因、字段缺失、分布和本轮判断边界。

triage_results.csv

结构化结果可继续分析，包含 `classification_source`、`llm_error` 和人工复核标记。

weekly_summary.md

从结构化结果生成产品周报摘要，列出优先级、用户证据、建议跟进和复核状态。

run_log.md

记录七个固定工具步骤的输入摘要、输出摘要、warnings、fallback 和下一步动作。

review_decisions.csv

承接人工复核队列，可填写确认、调整、保持开放或待处理，再生成 reviewed 结果。

report.html

静态 HTML 报告汇总运行总览、分布、复核样本、用户需求、问题卡片摘要和判断边界。

想实际操作？

启动本地 Web App，就能在网页里跑一次分诊。

v0.9.1 同时提供线上 Vercel Demo 和本地 FastAPI Web App。Agent 自动导出 review_decisions.csv，人工确认或调整后生成独立 reviewed 结果；原始分诊证据不会被覆盖。Ask 入口可用自然语言选择样例、上传 CSV、只用规则或生成 HTML 报告。

本地启动命令

python -m feedback_triage_agent.web_app

启动后打开 http://127.0.0.1:8000。也可以直接访问线上 Demo：feedback-triage-agent.vercel.app。Web App 不接数据库、不做登录、不接生产系统。

网页里可以做什么

1选择 `sample_feedback.csv`、`ai_app_reviews.csv` 或上传 CSV。
2选择是否使用 LLM 初稿、是否只用规则、是否生成 HTML 报告。
3点击“开始分诊”，在结果页查看总览、分布、人工复核队列、问题卡片、HTML 报告、QA 报告和 run log。
技术读者如何复现

从数据准备到样例报告，命令是可复跑的。

以下命令在项目根目录执行。展示页本身不需要 Python 环境，只有重新生成数据和报告时才需要。

python scripts/prepare_ai_app_reviews.py
python -m feedback_triage_agent.web_app
python -m feedback_triage_agent.cli ask "分析 data/ai_app_reviews.csv，输出问题卡片、人工复核队列和 HTML 报告"
python -m feedback_triage_agent.cli report --output data/output_ask
python -m feedback_triage_agent.cli inspect --output data/output_ask
python -m feedback_triage_agent.cli evaluate --input data/evaluation_feedback.csv --output data/evaluation_output
python -m feedback_triage_agent.cli review-apply --output data/output
python -m pytest

保留边界，才方便复核。

不接数据库、不做 Streamlit、不做 RAG，不把 API key 写进代码。展示页不接后端；v0.9.1 Web App 不接生产系统，复核结果通过本地 CSV 保存。
