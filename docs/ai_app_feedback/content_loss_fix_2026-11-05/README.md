## 最小产品改动

- `rules.py`：先按局部语句/转折切分，识别持久化对象、消失谓词及事件顺序，再区分当前报告、排除语境及明确恢复。处理对象继承、未保存、主动删除、竞品、模型记忆、否定/假设，以及恢复不能解决另一个对象的当前事件。纯假设的“已经找回”不会被当作实际恢复。
- 共享否定前缀只在当前语句内生效；正向风险豁免也限制到当前语句。否定广告不再否定后续闪退/丢失，过去“没有闪退”不再全文豁免今天实际闪退。
- 已识别数据事件覆盖评分和混合好评；保存/查找该对象、希望恢复的语气不再单独把它变成UI或产品定位问题。其他独立风险保留；崩溃+丢失保留原有类别成员和有依据的主类选择。
- `detect_human_review_reasons` 写入疑似/恢复待确认原因。已恢复历史不单独支撑当前P0，但仍需人工复核恢复状态，不确认、不关闭任务。
- 初步修复在 A06 仍被高星/正向过滤，之后才给 `observation._record_categories` 增加**仅限已识别未解决数据事件**的保护，沿用规则类别成员。没有修改问题簇风险、置信度或复核阈值，也未全面改造正向/主体归属/严重幻觉政策。

算法是确定性的局部事件规则，不是通用语言理解；没有样本ID、App名、整段原文特判或真实模型调用。另有直接否定“并非/不是”和“将来可能会消失”的未来咨询保护，避免把未发生的事件当作当前报告。
