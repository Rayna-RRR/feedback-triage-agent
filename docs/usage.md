# 使用教程：在本地跑通反馈风险工作台

本教程以当前 `main` 为准，面向第一次使用的人。完整操作请在本地完成。

| 入口 / 状态 | 当前能保证什么 |
| --- | --- |
| 本地 | 可完成创建、导入、比较、人工复核与审计；任务保存在本机 JSON 文件中。 |
| [当前线上临时预览](https://feedback-triage-agent.vercel.app/demo) | 仅供临时体验；使用临时存储，创建或跳转后也可能无法读取任务，不保证保存。 |
| [PR #14](https://github.com/Rayna-RRR/feedback-triage-agent/pull/14) | 持久化实现已通过本地验证与 [CI](https://github.com/Rayna-RRR/feedback-triage-agent/actions/runs/42290226752)，尚未完成云端验收、合并或上线。 |

教程更新不代表线上任务读取故障已修复。云数据库配置和生产发布继续暂停。

## 1. 启动本地服务

需要 **Python 3.9+** 和终端；基础流程使用本地规则，**不需要模型 API Key**。首次安装依赖需要网络。先下载或克隆仓库并进入仓库根目录（能看到 `pyproject.toml`），在 macOS / Linux 终端执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
python -m feedback_triage_agent.web_app
```

如果安装时提示旧版 pip 不支持 editable / pyproject.toml，先在已激活的虚拟环境中执行 `python -m pip install --upgrade pip`，再重试安装命令。

保持终端运行，打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)，点击 **“体验演示任务”**。演示任务由仓库内合成示例生成，不代表真实用户或生产结果。

## 2. 看证据并记录一次人工判断

1. 在“观察窗口”选择 **48h**，点击“应用筛选”；首次阅读保持“全部来源”。示例导入的是 48h 快照，先按这个口径阅读。
2. 查看“问题簇”：对照基线与当前的数量、占比和变化状态，再阅读“风险依据”及证据缺口。风险等级、变化状态和人工复核状态分别表示不同判断。
3. 展开原文证据，核对反馈 ID、来源、版本、所属窗口与原话。数量变化不等于版本导致了问题。
4. 展开 **“人工复核与处理”**，在“操作”中选择自己的判断，例如“确认风险结论”或“保持观察”；在“操作说明”写依据，填写“负责人”和“下一步动作”，按需选择“处理状态”。
5. 点击 **“记录本次操作”**。刷新页面，检查问题簇状态、负责人和动作，再到“运行与人工留痕”（导航为“审计记录”）核对新增记录。演示任务已有一条示例复核，注意区分自己刚提交的操作。

## 3. 创建自己的观察任务并导入 CSV

先用现有合成文件练习：返回首页，点击“创建观察任务”，填写任务名称（如“【合成练习】v2.4 观察”）、产品名称 `Acme Copilot（合成练习）`、基线版本 `v2.3` 和当前版本 `v2.4`。这些都是示例名称与版本。

选择“同等长度窗口（默认）”，按下表填写起止时间；界面中未带时区的时间按 UTC+08:00 解释。后续窗口可留空，系统会从当前窗口结束时间顺延同等时长；本例也可显式填写。

| 数据窗口 / 版本 | 起止时间（UTC+08:00） | 仓库根目录下的合成 CSV |
| --- | --- | --- |
| 基线 / `v2.3` | 2026-07-01 00:00 → 2026-07-03 00:00 | [artifacts/acceptance_v1.0/data/baseline_48h.csv](../artifacts/acceptance_v1.0/data/baseline_48h.csv) |
| 当前 / `v2.4` | 2026-07-03 00:00 → 2026-07-05 00:00 | [artifacts/acceptance_v1.0/data/current_48h.csv](../artifacts/acceptance_v1.0/data/current_48h.csv) |
| 后续（可选）/ `v2.4` | 2026-07-05 00:00 → 2026-07-07 00:00 | [artifacts/acceptance_v1.0/data/followup_48h.csv](../artifacts/acceptance_v1.0/data/followup_48h.csv) |

点击“创建并进入工作台”，找到“导入观察窗口反馈”，逐份导入：

- **基线文件：**“数据窗口”选“基线版本”，选择 `baseline_48h.csv`。
- **当前文件：**“数据窗口”选“当前版本”，选择 `current_48h.csv`。
- **后续文件（可选）：**“数据窗口”选“后续版本窗口”，选择 `followup_48h.csv`，用于查看“后续相对当前”。

每次均选“累计快照（推荐）”、观察窗口“发版后 48h”，反馈来源填 `App Store`（沿用合成文件的来源标记），再点击“校验并导入”。核对“最近导入记录”，随后切到 48h 查看比较。三个文件各 30 条合成反馈；后续数据单独保存，不应追加进“当前版本”。

换成自己的 CSV 时，填写真实产品、版本、窗口与来源，建议提供稳定 `id`、`source`、`review_text`；`rating` 可缺省，提供时须为 1–5。已有的 `created_at`、`version` 应与所选窗口一致。只能导出新增记录时可选“增量数据”；能导出完整窗口时优先用累计快照。

**不要给公开评论编造版本或时间。** 仓库 `data/ai_app_feedback/` 的公开评论缺少完整版本与观察窗口，不能套用上表做发版前后比较；请按[公开资料与复现流程](ai_app_feedback/README.md)用于单批次分诊和方法展示，保留原标注。

## 4. 保存位置与再次启动

默认任务文件为仓库内的 `data/observation_tasks/<task_id>/observation_state.json`，包含导入、人工处理和审计状态。保留该目录后，本地服务重启仍可读取；如设置过 `FEEDBACK_RISK_TASKS_DIR`，则保存到指定目录，再次启动时须使用同一配置。这是本机文件保存，没有云端备份。

在运行终端按 `Ctrl+C` 停止服务。下次回到**同一仓库根目录**执行：

```bash
source .venv/bin/activate
python -m feedback_triage_agent.web_app
```

打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)，从“版本观察任务”进入已有任务，无需重新安装依赖或重新导入。
